# 품질 검증 패턴 상세 (Quality Verification Patterns)

하네스 엔지니어링의 핵심은 "결정론적 품질 검증"이다. 다음 5대 품질 검증 패턴을 단독 혹은 결합하여 하네스 워크플로우에 적용한다.

---

## 1. 적대적 검증 (Adversarial Verification)

### 개념
- 구현을 담당한 에이전트(Producer)와 별개로, **"이 구현이 왜 실패할 수밖에 없는가"**를 집요하게 찾는 비판자(Adversarial Critic)를 배치한다.
- 비판자는 단순한 칭찬이나 피상적 확인을 배제하고 다음 판정 결과를 구조화하여 반환한다:
  - `confirmed`: 재현 가능한 버그나 논리적 오류가 명백히 입증됨.
  - `refuted`: 의심했으나 코드 분석 및 테스트 결과 정상임이 입증됨.
  - `uncertain`: 근거가 불충분하여 판단 유보.
- `confirmed` 판정 항목만 이슈로 등록하고 프로듀서에게 수정을 요구한다.

## 2. 심사위원단 (Judge Panels)

### 개념
- 복잡한 아키텍처나 UI 디자인 결정 시, 단일 모델의 첫 번째 생성안에 의존하지 않고 2~3개의 독립된 후보안을 생성한 후 다자간 심사를 진행한다.
- **평가 매트릭스 예시**:
  - 확장성 (Scalability): 가중치 25%
  - 성능 및 반응성 (Performance): 가중치 25%
  - 개발 생산성 및 가독성 (Maintainability): 가중치 25%
  - 보안 및 안정성 (Security): 가중치 25%
- 최고 득점안을 최종 채택하거나, 각 후보안의 핵심 장점만을 결합한 하이브리드안을 도출한다.

---

## 3. Loop-until-dry (발견 0건 수렴 루프)

### 개념
- 취약점 점검, 타이핑 오류 점검, 브라우저 콘솔 에러 탐색 등에서 결함 발견 건수가 연속으로 0건이 될 때까지 검사-수정 루프를 회전한다.
- **안전 제동 장치 (Safety Ceiling)**:
  - 무한 루프를 방지하기 위해 최대 반복 횟수(Max Iterations: 3~5회)를 설정한다.
  - 루프마다 발견 건수의 추이(`N_t < N_{t-1}`)를 모니터링하여 수렴하지 않으면 사용자에게 알림을 보낸다.

---

## 4. 다각 스윕 (Multi-angle Sweeps)

### 개념
- 전체 시스템을 서로 완전히 다른 독립 축(Axial perspectives)으로 병렬 점검한다.
- **대표 점검 축**:
  - 축 1: **보안 및 권한 스윕** (인증 누락, XSS, CSRF, 인젝션, 민감 정보 노출)
  - 축 2: **성능 및 리소스 스윕** (N+1 쿼리, 불필요한 리렌더링, 메모리 누수, 번들 크기)
  - 축 3: **접근성 및 UX 스윕** (스크린리더 지원, 키보드 네비게이션, 모바일 반응형 뷰포트)
  - 축 4: **도메인 정합성 스윕** (비즈니스 요구사항 및 예외 케이스 처리)

---

## 5. 누락 검토자 (Completeness Critic)

### 개념
- 개발 완료 선언 직전에 투입되는 최종 관문 에이전트.
- 코드를 새로 작성하지 않고 오직 **"원래 요구사항 대비 빠진 것이 무엇인가?"**에만 집중한다.
- 체크리스트:
  - 미구현된 엣지 케이스 (Null/Undefined, 네트워크 타임아웃, 빈 배열)
  - 누락된 단위 테스트 및 E2E 시나리오
  - 갱신되지 않은 문서, README, 타입 정의
