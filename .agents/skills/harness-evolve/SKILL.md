# Harness Evolve for Gemini — 하네스 진화 메커니즘

하네스는 한 번 만들고 끝나는 정적 문서가 아니라, 프로젝트의 실행 경험과 교훈을 흡수하며 발전하는 **자가 진화 시스템(Self-Evolving System)**이다.
본 스킬은 실행 과정에서의 성공/실패 델타를 포착하여 시스템 원리로 일반화하고, 에이전트, 스킬, `GEMINI.md`에 환류한다.

```
초기 하네스 ──▶ 실제 프로젝트 개발 수행 ──▶ 현재 하네스
                                             │
                                             ▼ (harness-evolve로 델타 분석)
                                      피드백 일반화 & 근본 원인(Why) 규명
                                             │
                                             ▼
                                  에이전트 / 스킬 / GEMINI.md 갱신
                                             │
                                             ▼
                                  다음 작업은 고도화된 초안에서 출발
```

## 진화 워크플로우

### Phase 1: 델타 및 실행 흔적 수집
1. 워크스페이스 내 `GEMINI.md`, `AGENTS.md`, `.agents/rules/`, `.agents/skills/`를 읽는다.
2. Git 이력이 있는 경우 하네스 파일들의 최근 커밋 로그를 확인한다.
3. 실제 실행 흔적 및 산출물 점검:
   - 정의된 파이프라인 경로에 결과 파일이 정상 생성되었는가?
   - 작성된 코드와 산출물이 스킬에 명시된 품질 기준(테스트 커버리지, 디자인 가이드 등)을 충족하는가?
4. **관찰 기반 진화 신호 감지 (사용자가 직접 말하지 않아도 선제 제안)**:
   - 동일한 버그 수정 또는 리팩터링 요청이 2회 이상 반복된 흔적
   - 린트/타입 에러 수정에 과도한 턴이 소모된 패턴
   - UI 스타일 또는 레이아웃에 대한 사용자 지적이 누적된 패턴

### Phase 2: 피드백 분류 및 수정 대상 매핑

| 피드백 유형 | 수정 및 반영 대상 | 예시 대응 |
| :--- | :--- | :--- |
| **산출물 품질 미흡** | 해당 도메인의 전용 스킬 (`.agents/skills/<name>/SKILL.md`) | 검증 체크리스트 및 구체적 기준 추가 |
| **에이전트 역할 누락** | 에이전트 정의 및 팀 구성 | 보안/성능 전담 Critic 에이전트 신설 안내 (`harness` 스킬 연계) |
| **실행 흐름 비효율** | 오케스트레이터 및 워크플로우 단계 | 병렬 실행 가능한 단계를 Fan-out으로 재배치 |
| **스킬 미호출/오작동** | 스킬 YAML Frontmatter `description` | 트리거 키워드 및 호출 조건 확장 |
| **모델 티어 부적합** | 모델 배정 설정 | 단순 작업에 고비용 Pro 모델이 남발된 경우 Flash로 전환 |

### Phase 3: 원리 수준 일반화 (Generalization)
1. **과적합(Overfitting) 방지**:
   - 단일 특정 오류에 대한 단편적 예외 규칙을 무작정 추가하지 않는다.
   - "이 오류가 왜 발생했는가?"의 구조적 원인을 파악하여, 유사한 모든 상황을 예방할 수 있는 **일반화된 원칙(Engineering Principle)**으로 승격한다.
2. **근본 이유(Why) 병기**:
   - 지침을 수정할 때 반드시 "왜 이 규칙이 존재하는가"에 대한 배경 맥락을 함께 기록하여 에이전트가 변형된 상황에서도 올바른 결정을 내리게 한다.
3. **퇴행(Regression) 방지**:
   - 과거에 적용한 변경 사항과 상충되는지 점검한다.

### Phase 4: `GEMINI.md` 변경 이력 갱신 및 검증
1. `GEMINI.md`의 **변경 이력 (Harness Changelog)** 테이블에 일자, 내용, 대상, 사유를 공식 기록한다.
2. 수정된 스킬 및 룰의 문법과 링크 무결성을 검증한다.
3. 필요한 경우 Antigravity의 내장 슬래시 커맨드 `/learn`을 사용자에게 추천하여 IDE 레벨에서도 학습되도록 유도한다.

### Phase 5: 진화 완료 보고
- 포착된 핵심 델타 및 병목 요약
- 새롭게 정립되어 일반화된 규칙 설명
- 향후 작업 시 기대되는 품질 및 속도 향상 지표 제시
